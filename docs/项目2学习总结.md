# 项目 2 学习总结：EchoMind — 智能客服 AI 系统

## 项目概述

**EchoMind** 是一个可以直接 Docker 部署运行的企业级智能客服项目，覆盖了 AI Agent 方向秋招面试的**六大核心考点**。

**特点**：
- 代码精简，每个模块聚焦一个技术亮点
- 附带完整的 wiki 文档
- 适合 AI Agent / LLM 应用方向求职

---

## 一、六大核心考点

### 1. 端到端意图识别（三路融合 + 加权投票）

**设计思路**：
```
用户消息
  ↓
三路识别并行执行
├── LLM 识别（语义理解强）
├── 关键词匹配（速度快、成本低）
└── 规则匹配（确定性高）
  ↓
加权投票 → 最终意图
```

**优势**：
- 比单用 LLM 更准确、更稳定
- 降低成本（简单问题不用 LLM）
- 可解释性强

**我们可以借鉴**：
- Phase 4 意图识别可以采用这种设计

---

### 2. MCP 工具调用框架（查询改写 + LLM 重排）

**设计思路**：
```
用户问题
  ↓
查询改写（Query Rewriting）
  ↓
检索（Retrieval）
  ↓
LLM 重排（Reranking）
  ↓
返回结果
```

**解决的问题**：
- 召回不全：通过查询改写，生成多个变体
- 召回不好：通过 LLM 重排，提升相关性

**我们可以借鉴**：
- Phase 5 RAG 知识检索可以采用这种设计

---

### 3. 多轮对话记忆管理（三级记忆 + 自动压缩）

**三级记忆架构**：

| 层级 | 名称 | 内容 | 保留策略 |
|------|------|------|----------|
| L1 | 工作记忆 | 最近 5 轮完整对话 | 完整保留 |
| L2 | 短期记忆 | 最近 20 轮摘要 | 自动压缩 |
| L3 | 长期记忆 | 历史所有，用户画像 | 持久化存储 |

**自动压缩**：
- 超过 5 轮：旧对话压缩成摘要
- 摘要保留关键信息：订单号、用户偏好等

**我们可以借鉴**：
- Phase 6 三级记忆系统

---

### 4. 多 Agent 路由编排（意图路由 + 性能路由 + 降级）

**三种路由**：

| 路由类型 | 作用 | 例子 |
|----------|------|------|
| 意图路由 | 根据意图分配 Agent | 查订单 → OrderAgent |
| 性能路由 | 负载均衡 | 多个 Agent 实例轮询 |
| 降级 | 超时或失败时兜底 | 返回兜底回复 |

**降级策略**：
- 超时降级：返回"系统繁忙"
- 失败重试：最多重试 2 次
- 熔断机制：连续失败时暂时关闭

**我们可以借鉴**：
- Phase 8 多 Agent 编排

---

### 5. Monitor 闭环监控（在线表现驱动路由权重动态调整）

**闭环流程**：
```
监控 → 数据分析 → 权重调整 → 优化效果
  ↑                               ↓
  └───────────────────────────────┘
```

**监控指标**：
- 工具调用成功率
- 响应时间
- 用户满意度
- 意图识别准确率

**动态调整**：
- 根据在线表现调整路由权重
- 表现好的 Agent 分配更多流量

**我们可以借鉴**：
- Phase 9 生产化

---

### 6. 端到端评测（LLM-as-Judge 四维度打分）

**四维度打分**：

| 维度 | 问题 | 分数范围 |
|------|------|----------|
| 准确性 | 回答是否正确？ | 1-5 分 |
| 完整性 | 是否回答了所有问题？ | 1-5 分 |
| 相关性 | 是否紧扣问题？ | 1-5 分 |
| 流畅性 | 语言是否自然？ | 1-5 分 |

**LLM-as-Judge**：
- 让 LLM 当评委
- 从四个维度打分
- 生成评测报告

**我们可以借鉴**：
- Phase 7 评测体系
