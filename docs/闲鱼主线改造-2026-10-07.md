## 核心约束

- 闲鱼入口校验平台数字买家/商品 ID，买家 JWT 只能使用自己的合成用户会话，不能指定任意会话。
- 浏览器需闲鱼配置租户的 ADMIN JWT；CUSTOMER、其他租户 ADMIN 不能编辑商品或接管会话。服务令牌只用于侧车。
- 未审核描述及成色不进入买家事实；草稿编辑不覆盖发布内容。平台价格/库存高于发布资料，发布不能把已售库存回退为有货。
- 已发布的逐商品授权优先于配置兜底；底价等内部规则不放入商品事实或 RAG。授权撤销后成交确认重新校验。
- 型号通用能力不证明当前商品已实测正常；型号未确认不引用具体型号说明书。新增接待资料标注项目来源，不冒充厂商手册或平台政策。
- 事实文件持久化失败不能返回成功；恢复损坏文件时失败关闭，避免回退到旧库存。
- 卖家接管可取消延迟自动回复；恢复经 Java 确认。重复句号不重复切换，卖家消息重投不重复写历史。
- 外部结果不明不宣称失败、成功或自动重发。WebSocket SENT 表示连接写入，缺少平台送达确认。

## 使用与配置

1. Java 显式配置私有 JWT 密钥；侧车开启时配置 `SMARTCS_XIANYU_ENABLED` 和独立服务令牌。
2. 真实接入启用 `SMARTCS_PERSISTENCE_MODE=jdbc`；Java 创建 `cs_message_inbox` 表保存聊天/卖家消息回执。Memory 模式只用于本地，进程重启不保留回执，容量 20,000 条，满后拒绝新消息。
3. 挂载 `SMARTCS_XIANYU_ITEM_SNAPSHOT_DIR`：`profiles/` 保存商品草稿、发布内容、版本与审核人；`overrides/` 保存平台价格、库存。侧车状态和 SQLite 日志也需持久化。
4. 平台首次快照创建待审核商品，工作台核对商品实况、品类、型号、配件和授权，先保存再发布。两个请求都携带 `expectedVersion`，冲突后重新加载核对。
5. 工作台会话控制输入实际买家 ID、商品 ID；人工原文在闲鱼客户端发送。结果未知的核查方法见 [侧车说明](../sidecar/xianyu/README.md)。

现在按一个配置卖家租户、一个 Java 实例和一个侧车进程实现；同一 SQLite 日志不供多个侧车进程共同消费；文件 CAS 不提供多个 Java 进程间的同步。尚未建设多卖家账户平台、全量会话列表或平台订单接口。商品事实有缓存 TTL，不能声称实时观察全部平台变更。未知消息回执需人工核查，尚未提供统一复核页面或数据库保留期清理任务。

## 验证

本次全部使用本地测试与临时数据，不访问真实 Cookie、闲鱼平台或生产服务器。

- 后端：740 项中 739 项通过、1 项真实模型用例跳过；新增覆盖消息回放/并发/内容冲突/UNKNOWN、JDBC 重建、商品审核 CAS、事实持久化失败、渠道知识范围、真实 JWT 权限和卖家协作。
- 前端：12 项测试通过，包括 Demo issuer 关闭后的卖家登录、旧请求中止、凭据失效清除；TypeScript 与生产构建通过。
- 侧车：42 项离线测试通过，覆盖批量、重投、容量、会话顺序、人工打断、HTTP/发送状态恢复和改价/售出同步失败。
- 默认 JAR 打包、启动和 readiness 检查通过；本地浏览器确认商品草稿编辑时禁止发布，保存后版本递增，审核发布后显示已发布资料。最终 JAR 重启后，商品审核版本与现势价格库存恢复正确；测试数据仅存于临时目录。

历史真机收发记录仍以客服Agent-76、客服Agent-78 为依据。本次改造不等于已部署上线或已完成新的真机收发复验。
