# 售后工单与 SLA 履约平台：架构设计

## 1. 架构目标

本项目优先采用模块化单体架构，而不是一开始拆成微服务。

原因：

- 秋招项目更需要体现业务建模和工程基本功。
- 单体更容易保证事务边界清晰。
- 后期可以按模块平滑拆分。
- 避免为了“微服务”引入过多部署复杂度。

架构目标：

- 核心业务同步完成。
- 非核心动作异步化。
- 关键状态变更可追踪。
- 事件发布可靠。
- 查询和搜索能力分离。
- 方便后续接入客服 Agent。

## 2. 总体架构

```text
用户 / 客服 / 管理员 / 客服 Agent
        |
        v
API Controller
        |
        v
Application Service
        |
        v
Domain Model / Domain Service
        |
        v
Repository / Infrastructure
        |
        +--> MySQL
        +--> Redis
        +--> RabbitMQ
        +--> Elasticsearch
```

## 3. 分层说明

Controller 层：

- 接收 HTTP 请求。
- 参数校验。
- 用户身份解析。
- 调用应用服务。
- 返回统一响应。

Application Service 层：

- 编排业务用例。
- 控制事务边界。
- 调用领域服务。
- 写入 Outbox 事件。
- 调用仓储接口。

Domain 层：

- 表达核心业务规则。
- 校验状态流转。
- 计算 SLA 截止时间。
- 判断是否可以分配、接单、关闭。

Infrastructure 层：

- MySQL 访问。
- Redis 访问。
- MQ 发送和消费。
- Elasticsearch 索引同步。
- 外部通知适配。

## 4. 模块划分

```text
ticket-platform
  user        用户、角色、权限
  ticket      工单核心
  assignment  派单
  sla         SLA 规则、计时、升级
  notify      通知
  event       领域事件、Outbox、MQ
  search      Elasticsearch 同步与查询
  statistics 统计报表
  agent       客服 Agent 对接
```

## 5. 创建工单流程

```text
请求创建工单
  -> 参数校验
  -> 创建 Ticket
  -> 计算 SLA 截止时间
  -> 执行派单策略
  -> 保存工单
  -> 保存操作日志
  -> 写入 Outbox 事件
  -> 事务提交
  -> 异步发布 MQ
  -> 通知负责人
  -> 同步 ES 索引
```

关键点：

- 工单、日志、Outbox 在一个本地事务内提交。
- MQ 发送不直接放在业务事务中。
- 通知和 ES 同步失败不影响工单创建。

## 6. 状态变更流程

```text
请求状态变更
  -> 查询工单
  -> 权限校验
  -> 状态机校验
  -> 修改状态
  -> 保存操作日志
  -> 写入状态变更事件
  -> 异步通知
  -> 异步同步搜索索引
```

关键点：

- 状态变更必须经过状态机。
- 每次状态变更都记录操作日志。
- 消费端基于事件 ID 做幂等。

## 7. 事务边界

强一致：

- 工单主表写入。
- 工单操作日志写入。
- SLA 任务写入。
- Outbox 事件写入。

最终一致：

- 通知发送。
- ES 索引同步。
- 统计数据刷新。
- SLA 超时升级通知。

## 8. 消息事件设计

| 事件 | 触发时机 | 消费方 |
| --- | --- | --- |
| `TicketCreatedEvent` | 工单创建后 | 通知、搜索、统计 |
| `TicketAssignedEvent` | 工单分配后 | 通知、统计 |
| `TicketStatusChangedEvent` | 状态变更后 | 通知、搜索、统计 |
| `SlaDeadlineReachedEvent` | SLA 超时后 | 通知、升级 |
| `TicketClosedEvent` | 工单关闭后 | 统计、归档 |

## 9. Redis 使用场景

Redis 不承载核心真实数据，只做加速和控制。

- 工单列表热点查询缓存。
- 用户权限信息缓存。
- SLA 规则缓存。
- 创建工单接口限流。
- 派单时的短期负载计数。
- 防止重复提交的幂等 Token。

## 10. Elasticsearch 使用场景

MySQL 负责核心数据，Elasticsearch 负责搜索体验。

索引内容：

- 工单 ID。
- 标题。
- 描述。
- 分类。
- 状态。
- 优先级。
- 客户 ID。
- 负责人 ID。
- Agent 摘要。
- 最近处理内容。
- 创建时间、更新时间。

同步方式：

- 工单变更后写 Outbox。
- MQ 消费事件后更新 ES。
- 如果同步失败，进入重试或补偿任务。
