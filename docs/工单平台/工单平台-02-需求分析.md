# 售后工单与 SLA 履约平台：需求分析

## 1. 业务背景

售后服务中，用户的问题往往无法一次性解决。例如退款异常、设备故障、账号问题、物流争议、技术排障等，都需要被记录、分配、跟踪和关闭。

客服 Agent 可以承担问题识别和初步回答，但对于无法直接解决的问题，需要进入工单履约流程。本系统负责把用户问题转化为可追踪的工单，并保证处理过程透明、可控、可统计。

## 2. 角色需求

客户：

- 创建工单。
- 查看自己的工单列表和详情。
- 补充问题描述、图片或附件链接。
- 查看处理进度。
- 确认问题已解决。

客服：

- 查看分配给自己的工单。
- 接单、处理、回复用户。
- 修改工单分类、优先级、负责人。
- 转派给技术支持或其他技能组。
- 标记工单已解决。

技术支持：

- 查看转派给自己的技术类工单。
- 补充技术排查结论。
- 将工单退回客服或标记处理完成。

管理员：

- 查看全部工单。
- 管理用户、角色、技能组。
- 配置 SLA 规则。
- 处理超时升级工单。
- 查看统计报表。

客服 Agent：

- 通过接口创建工单草稿或正式工单。
- 传入用户原始对话、摘要、意图、分类、置信度。
- 给出优先级建议。

## 3. 功能需求

### 3.1 工单管理

创建工单来源可以是用户手动创建，也可以是客服 Agent 自动创建。

必填信息：

- 标题。
- 问题描述。
- 客户 ID。
- 问题分类。
- 优先级。
- 来源渠道。

可选信息：

- 订单号。
- 商品 ID。
- 附件链接。
- Agent 对话摘要。
- Agent 置信度。

查询条件：

- 工单编号。
- 标题关键词。
- 客户 ID。
- 负责人 ID。
- 状态。
- 优先级。
- 分类。
- 创建时间范围。
- 是否超时。

详情页展示：

- 基本信息。
- 当前状态。
- 负责人和技能组。
- SLA 截止时间。
- 处理记录。
- 操作日志。
- 通知记录。

### 3.2 状态流转

系统需要保证工单只能按照合法路径流转，不能由任意接口直接修改状态。

核心动作：

- 分配。
- 接单。
- 请求用户补充。
- 用户补充信息。
- 转技术支持。
- 标记解决。
- 用户确认关闭。
- 取消。
- 重新打开。

### 3.3 派单

第一版使用规则派单。

派单依据：

- 问题分类。
- 产品线。
- 技能组。
- 当前人员待处理工单数。
- 工单优先级。

派单策略：

- 优先分配给匹配技能组中负载最低的人。
- 如果没有可用人员，分配到技能组公共队列。
- 高优先级工单可以优先分配给高级客服。

### 3.4 SLA 管理

| 优先级 | 首次响应时限 | 解决时限 |
| --- | --- | --- |
| P0 | 10 分钟 | 2 小时 |
| P1 | 30 分钟 | 8 小时 |
| P2 | 2 小时 | 24 小时 |
| P3 | 8 小时 | 72 小时 |

超时处理：

- 首响超时：通知负责人和组长。
- 解决超时：升级给管理员。
- 多次超时：提高工单优先级。

### 3.5 通知

通知类型：

- 工单创建通知。
- 工单分配通知。
- 状态变更通知。
- 用户补充信息通知。
- SLA 即将超时通知。
- SLA 已超时通知。

第一版可以用站内信表和日志模拟通知。

### 3.6 搜索与统计

普通条件查询走 MySQL，关键词搜索走 Elasticsearch。

统计指标：

- 每日新增工单数。
- 各状态工单数。
- 各分类工单数。
- 平均首次响应时长。
- 平均解决时长。
- SLA 超时率。
- 客服人均处理量。

## 4. 非功能需求

性能：

- 工单列表查询 P95 小于 300ms。
- 创建工单接口 P95 小于 200ms。
- 支持 10 万级工单数据的分页查询。

一致性：

- 工单创建和操作日志写入必须在同一事务中完成。
- 工单状态变更和事件发布需要保证最终一致。
- MQ 消费必须支持幂等。

可用性：

- MQ 消费失败需要重试。
- 通知失败不能影响主链路。
- SLA 任务可以重复扫描，但不能重复升级。

安全：

- 客户只能查看自己的工单。
- 客服只能查看自己或所在技能组的工单。
- 管理员可以查看全部工单。
- 重要操作需要记录审计日志。

## 5. 核心接口草案

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/tickets` | 创建工单 |
| GET | `/api/tickets` | 查询工单列表 |
| GET | `/api/tickets/{id}` | 查询工单详情 |
| POST | `/api/tickets/{id}/assign` | 分配工单 |
| POST | `/api/tickets/{id}/accept` | 接单 |
| POST | `/api/tickets/{id}/reply` | 回复或处理 |
| POST | `/api/tickets/{id}/resolve` | 标记解决 |
| POST | `/api/tickets/{id}/close` | 关闭工单 |
| POST | `/api/tickets/{id}/cancel` | 取消工单 |
| GET | `/api/sla/rules` | 查询 SLA 规则 |
| POST | `/api/sla/rules` | 创建 SLA 规则 |
| GET | `/api/statistics/tickets` | 工单统计 |
| POST | `/api/agent/tickets` | Agent 创建工单 |

## 6. 验收标准

- 能完整演示从 Agent 创建工单到人工处理关闭的流程。
- 任意状态流转都经过状态机校验。
- SLA 超时可以自动触发升级事件。
- MQ 消费支持失败重试和幂等。
- 工单列表在大数据量下有明确索引设计。
- 有至少一份压测或查询优化记录。
