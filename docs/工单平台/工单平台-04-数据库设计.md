# 售后工单与 SLA 履约平台：数据库设计

## 1. 设计原则

- MySQL 保存核心业务事实。
- 状态字段使用明确枚举值，不使用含义模糊的数字。
- 高频查询字段建立组合索引。
- 操作日志只追加，不修改。
- 事件表用于可靠消息，不依赖业务代码直接发送 MQ。
- 表设计保留扩展字段，但不滥用 JSON。

## 3. 工单主表

```sql
CREATE TABLE ticket (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  ticket_no VARCHAR(32) NOT NULL,
  title VARCHAR(128) NOT NULL,
  description TEXT NOT NULL,
  customer_id BIGINT NOT NULL,
  assignee_id BIGINT NULL,
  skill_group_id BIGINT NULL,
  category VARCHAR(64) NOT NULL,
  priority VARCHAR(16) NOT NULL,
  status VARCHAR(32) NOT NULL,
  source VARCHAR(32) NOT NULL,
  order_no VARCHAR(64) NULL,
  product_id BIGINT NULL,
  agent_summary VARCHAR(512) NULL,
  agent_confidence DECIMAL(5,4) NULL,
  first_response_deadline DATETIME NULL,
  resolve_deadline DATETIME NULL,
  first_responded_at DATETIME NULL,
  resolved_at DATETIME NULL,
  closed_at DATETIME NULL,
  version INT NOT NULL DEFAULT 0,
  deleted TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_ticket_no (ticket_no),
  KEY idx_customer_status_created (customer_id, status, created_at),
  KEY idx_assignee_status_priority (assignee_id, status, priority),
  KEY idx_status_priority_created (status, priority, created_at),
  KEY idx_sla_response_deadline (first_response_deadline),
  KEY idx_sla_resolve_deadline (resolve_deadline)
);
```

字段说明：

- `ticket_no`：对外展示的工单编号，不直接暴露数据库 ID。
- `status`：工单状态，由状态机控制。
- `priority`：优先级，例如 `P0`、`P1`、`P2`、`P3`。
- `source`：来源，例如 `USER`、`AGENT`、`ADMIN`。
- `version`：乐观锁版本号，防止并发状态覆盖。
- `deleted`：逻辑删除标记。

## 4. 工单操作日志表

```sql
CREATE TABLE ticket_operation_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  ticket_id BIGINT NOT NULL,
  operator_id BIGINT NOT NULL,
  operation_type VARCHAR(32) NOT NULL,
  from_status VARCHAR(32) NULL,
  to_status VARCHAR(32) NULL,
  content VARCHAR(1024) NULL,
  created_at DATETIME NOT NULL,
  KEY idx_ticket_created (ticket_id, created_at),
  KEY idx_operator_created (operator_id, created_at)
);
```

设计重点：

- 日志只追加，不能更新。
- 状态变化记录 `from_status` 和 `to_status`。
- 用于审计、排查和详情页时间线。

## 5. 工单回复表

```sql
CREATE TABLE ticket_reply (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  ticket_id BIGINT NOT NULL,
  replier_id BIGINT NOT NULL,
  reply_type VARCHAR(32) NOT NULL,
  content TEXT NOT NULL,
  visible_to_customer TINYINT NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL,
  KEY idx_ticket_created (ticket_id, created_at)
);
```

## 6. SLA 规则表

```sql
CREATE TABLE sla_rule (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(64) NOT NULL,
  category VARCHAR(64) NULL,
  priority VARCHAR(16) NOT NULL,
  first_response_minutes INT NOT NULL,
  resolve_minutes INT NOT NULL,
  enabled TINYINT NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  KEY idx_category_priority_enabled (category, priority, enabled)
);
```

规则匹配建议：

1. 优先匹配分类 + 优先级。
2. 如果没有，匹配默认分类 + 优先级。
3. 如果仍没有，使用系统默认 SLA。

## 7. SLA 任务表

```sql
CREATE TABLE sla_task (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  ticket_id BIGINT NOT NULL,
  task_type VARCHAR(32) NOT NULL,
  deadline_at DATETIME NOT NULL,
  status VARCHAR(32) NOT NULL,
  triggered_at DATETIME NULL,
  retry_count INT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_ticket_task_type (ticket_id, task_type),
  KEY idx_status_deadline (status, deadline_at)
);
```

`task_type` 示例：

- `FIRST_RESPONSE`
- `RESOLVE`

`status` 示例：

- `PENDING`
- `TRIGGERED`
- `CANCELLED`

## 8. 通知表

```sql
CREATE TABLE notification (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  receiver_id BIGINT NOT NULL,
  ticket_id BIGINT NULL,
  type VARCHAR(32) NOT NULL,
  title VARCHAR(128) NOT NULL,
  content VARCHAR(1024) NOT NULL,
  read_status VARCHAR(16) NOT NULL,
  created_at DATETIME NOT NULL,
  read_at DATETIME NULL,
  KEY idx_receiver_read_created (receiver_id, read_status, created_at),
  KEY idx_ticket_created (ticket_id, created_at)
);
```

## 9. Outbox 事件表

```sql
CREATE TABLE outbox_event (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  event_id VARCHAR(64) NOT NULL,
  aggregate_type VARCHAR(64) NOT NULL,
  aggregate_id BIGINT NOT NULL,
  event_type VARCHAR(64) NOT NULL,
  payload JSON NOT NULL,
  status VARCHAR(32) NOT NULL,
  retry_count INT NOT NULL DEFAULT 0,
  next_retry_at DATETIME NULL,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_event_id (event_id),
  KEY idx_status_next_retry (status, next_retry_at),
  KEY idx_aggregate (aggregate_type, aggregate_id)
);
```

状态建议：

- `NEW`
- `PUBLISHING`
- `PUBLISHED`
- `FAILED`

面试表达：

> 业务数据和事件数据在同一个本地事务里落库，由异步任务扫描 Outbox 表发布 MQ，避免业务事务提交成功但消息发送失败。

## 10. 索引设计思路

客户查看自己的工单：

```sql
WHERE customer_id = ? AND status = ? ORDER BY created_at DESC
```

索引：

```sql
idx_customer_status_created (customer_id, status, created_at)
```

客服查看待处理工单：

```sql
WHERE assignee_id = ? AND status IN (...) ORDER BY priority, created_at
```

索引：

```sql
idx_assignee_status_priority (assignee_id, status, priority)
```

SLA 扫描：

```sql
WHERE status = 'PENDING' AND deadline_at <= ?
```

索引：

```sql
idx_status_deadline (status, deadline_at)
```

## 11. 并发控制

工单状态变更建议使用乐观锁：

```sql
UPDATE ticket
SET status = ?, version = version + 1, updated_at = ?
WHERE id = ? AND version = ?;
```

如果影响行数为 0，说明工单被其他请求修改，需要重新读取后再判断。
