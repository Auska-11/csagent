# 售后工单与 SLA 履约平台：项目定位与范围

## 1. 项目一句话

售后工单与 SLA 履约平台用于承接客服 Agent 无法自动解决的问题，完成工单创建、派单、处理、超时升级、通知和统计分析，形成从智能客服到人工履约的完整闭环。

## 2. 项目价值

客服 Agent 解决的是前台交互和问题理解，但真实业务不能停留在问答层面。退款异常、售后维修、技术排障、人工核查等问题，都需要进入一个可追踪、可分配、可升级、可统计的履约系统。

这个项目的价值：

- 对业务：让用户问题从“被回答”走向“被解决”。
- 对工程：覆盖状态机、事务、MQ、缓存、搜索、权限、统计、压测等 Java 后端核心能力。
- 对简历：和客服 Agent 项目组成完整产品叙事，避免两个项目互相孤立。

## 3. 项目边界

范围内：

- 工单创建、查询、详情、状态流转。
- 工单分类、优先级、技能组、负责人。
- SLA 规则配置、计时、超时升级。
- 操作日志、处理记录、通知记录。
- 异步事件：工单创建、状态变更、SLA 超时、通知发送。
- 权限控制：客户、客服、技术支持、管理员。
- 搜索与统计：关键词搜索、状态统计、处理效率统计。
- 与客服 Agent 对接：Agent 生成工单摘要、分类、优先级建议。

范围外：

- 不做完整 IM 聊天系统。
- 不做复杂审批流引擎。
- 不接真实短信、邮件付费服务，先用站内信或日志模拟。
- 不做完整微服务拆分，优先采用模块化单体。

## 4. 用户角色

| 角色 | 说明 | 典型操作 |
| --- | --- | --- |
| 客户 | 提交问题的人 | 创建工单、查看进度、补充信息、确认解决 |
| 客服 | 一线处理人员 | 接单、回复、转派、标记解决 |
| 技术支持 | 处理技术类问题 | 排查问题、补充解决方案、回写处理结果 |
| 管理员 | 管理后台用户 | 配置 SLA、技能组、统计报表、处理升级工单 |
| 客服 Agent | 智能入口 | 根据对话生成工单摘要、分类和优先级 |

## 5. 核心业务闭环

1. 用户向客服 Agent 咨询问题。
2. Agent 判断无法直接解决，生成工单草稿。
3. 工单平台创建工单，记录来源、摘要、分类、优先级。
4. 系统根据技能组、问题类型、人员负载自动派单。
5. SLA 计时开始，系统监控响应时限和解决时限。
6. 客服或技术支持处理工单，状态不断流转。
7. 超时则触发升级和通知。
8. 用户确认后工单关闭。
9. 后台统计响应时长、解决率、超时率、工单量趋势。

## 6. 技术栈建议

| 类别 | 技术 |
| --- | --- |
| 后端框架 | Spring Boot |
| ORM | MyBatis-Plus 或 Spring Data JPA |
| 数据库 | MySQL |
| 缓存 | Redis |
| 消息队列 | RabbitMQ 或 RocketMQ |
| 搜索 | Elasticsearch |
| 定时任务 | Spring Scheduling / XXL-JOB |
| 权限 | Spring Security + JWT |
| 接口文档 | Knife4j / Springdoc OpenAPI |
| 测试 | JUnit 5、Mockito |
| 压测 | JMeter / wrk |

## 7. 开发优先级

第一阶段：最小可用版本

- 用户和角色基础模型。
- 工单创建、列表、详情。
- 工单状态流转。
- 操作日志。
- 基础派单规则。

第二阶段：工程亮点版本

- SLA 规则和超时任务。
- MQ 异步事件。
- 通知模块。
- Outbox 可靠消息。
- Redis 缓存和限流。

第三阶段：简历增强版本

- Elasticsearch 搜索。
- 统计报表。
- Agent 对接。
- 压测报告和索引优化记录。
- 面试亮点总结。
