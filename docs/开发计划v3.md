# 智能客服 Agent 开发计划 v3.0

## 项目概述

项目名称：Smart CS Agent（智能客服 Agent）
技术栈：Java 17 + Spring Boot 3.3 + LangChain4j
项目目标：开发一个可写进简历、面试可深入讲解的 Agent 项目

---

## 核心原则

1. 聚焦：一次只做一个阶段，做完再规划下一步
2. 可验收：每个阶段有明确的验收标准
3. 可展示：每完成一个阶段都能运行和演示
4. 可讲解：每个功能都能在面试中说清楚

---

## 当前阶段：Phase 2 工具调用

### 目标

Agent 能识别用户意图，自动调用工具，返回真实数据。

### 验收标准

用户说：帮我查一下订单 ORD-001
Agent 回复：您的订单 ORD-001 已发货，商品是蓝牙耳机 Pro Max，物流单号 SF1234567890。

### 需要完成的任务

#### 任务 2.1：重写 OrderTools（使用 Repository）

当前状态：OrderTools 里有模拟数据，但没用 Repository
目标状态：OrderTools 调用 OrderRepository 获取数据

改动内容：
- 注入 OrderRepository
- 注入 ProductRepository（查订单时需要显示商品名）
- 修改 queryOrderStatus 方法，从 Repository 查询
- 修改 queryUserOrders 方法，查询用户所有订单

文件：src/main/java/com/smartcs/smart_cs_agent/tools/OrderTools.java

#### 任务 2.2：创建 UserTools

功能：
- queryUserInfo：根据 token 查询用户信息
- 参数：token
- 返回：用户ID、姓名、手机号

文件：src/main/java/com/smartcs/smart_cs_agent/tools/UserTools.java

#### 任务 2.3：创建 ProductTools

功能：
- queryProductInfo：查询产品详情（价格、库存、描述）
- searchProducts：根据关键词搜索产品
- 参数：产品名或关键词
- 返回：产品列表

文件：src/main/java/com/smartcs/smart_cs_agent/tools/ProductTools.java

#### 任务 2.4：创建 ReturnTools

功能：
- applyReturn：申请退换货
- queryReturnStatus：查询退换货进度
- 参数：订单号、原因
- 返回：申请结果或进度

文件：src/main/java/com/smartcs/smart_cs_agent/tools/ReturnTools.java

#### 任务 2.5：改造 Controller，注册工具

当前状态：LlmDemoController 只有基础对话
目标状态：Controller 能使用工具

改动内容：
- 注入所有 Tools
- 创建带工具的 ChatLanguageModel
- 改造 chat 方法，支持工具调用
- 添加 userId 参数，识别用户身份

文件：src/main/java/com/smartcs/smart_cs_agent/controller/AgentController.java（新建）

#### 任务 2.6：测试工具调用

测试用例：

用例 1：查询订单
  输入：帮我查一下订单 ORD-001
  预期：调用 OrderTools.queryOrderStatus，返回订单信息

用例 2：查询用户订单
  输入：我有哪些订单
  预期：调用 OrderTools.queryUserOrders，返回订单列表

用例 3：查询产品
  输入：蓝牙耳机多少钱
  预期：调用 ProductTools.queryProductInfo，返回价格信息

用例 4：申请退换货
  输入：我想退 ORD-004 这个订单，质量有问题
  预期：调用 ReturnTools.applyReturn，返回退换单号

用例 5：闲聊（不调用工具）
  输入：你好
  预期：直接回复，不调用任何工具

## 面试话术（Phase 2 完成后）

一分钟版本：

> 我做了一个智能客服 Agent，基于 LangChain4j 实现。
> 核心是工具调用机制：通过 @Tool 注解定义业务工具，
> LLM 自动识别用户意图并选择合适的工具执行。
> 为了支持系统扩展，我设计了分层架构：Repository 层
> 封装数据访问，Tools 层定义业务能力，两者通过接口
> 解耦，接入真实系统时只需替换 Repository 实现。

可深挖的问题：

Q: 工具调用失败怎么办？
A: 可以加入重试机制、降级策略、兜底回复。

Q: 怎么让 LLM 准确选择工具？
A: @Tool 的描述要清晰，参数用 @P 注解说明含义。

Q: 能同时调用多个工具吗？
A: LangChain4j 支持，LLM 可以决定并行调用多个工具。
