# Smart CS Agent 项目改进记录

日期：2026-10-07。方向：Java 后端 / AI 应用开发。对应 [2026-10-05 项目评审](项目评审-简历方向-2026-10-05.md)。

此次优先修复可复现的边界问题，补齐回归验证，并调整对外项目介绍。没有重新执行付费模型跑批、真实 MySQL/Qdrant 或闲鱼线上联调；历史实验数字仍按原报告日期与口径引用。

## 已完成的改进

| 范围 | 改进后的行为 | 回归依据 |
| --- | --- | --- |
| 实验基线 | 五个 baseline Bean 和 HTTP 入口默认不加载；显式实验只允许 memory 持久化、local Capability、memory 人工转接 | 默认客户/管理员请求均 404；实验结构与对照测试通过；拒绝 JDBC、远程 MCP、售后 HTTP 配置 |
| 基线历史 | 使用 `ConversationKey(tenantId, userId, conversationId)` | 同名会话跨用户/租户隔离；HTTP 测试验证另一用户无法取得原用户订单工具历史 |
| 用户偏好 | 使用 `UserMemoryKey(tenantId, userId)`；写入、推荐读取、HTTP 查询和删除全部传递租户 | 同名用户可保存不同偏好；两个租户的推荐各用自己的偏好；删除 B 不影响 A |
| JWT 配置 | 移除公开默认密钥；所有启动方式缺密钥、过短或使用已知开发密钥时失败 | Demo 开启/关闭两种模式、真实 Spring 属性绑定启动校验均覆盖；测试专用配置与发布资源分开 |
| Workflow 路由 | 引入 `WorkflowEligibilityPolicy`；闲鱼约束实现在渠道包，通用 Router 不再依赖渠道类 | 首次评分、粘性恢复和兜底均受策略限制；多个策略取交集；原闲鱼议价、售出保护与 SLA 用例通过 |
| MCP 方法子集 | 初始化请求发送版本/能力/客户端信息；支持 `ping`，接收无 id 通知并返回空 HTTP 202；客户端验证版本后发送 initialized 通知 | 客户端 HTTP mock 与服务端真实安全链覆盖；不支持的协商版本停止初始化；`id:null` 请求与省略 id 通知可区分；JSON-RPC 成功/错误字段互斥 |
| 侧车与 CI | 离线构造强制 ECHO；测试在临时路径验证文件“不创建、不覆盖”，关闭 mock 服务 socket；新增 Python 3.13 CI job | 现有侧车工作目录下 26 项离线测试通过，不需要删除本地状态文件；CI 配置已更新，GitHub 远端运行尚未触发 |
| 项目介绍 | 以确定性 Workflow 路由和专家域标签描述现有实现；更新 README、启动配置和面试手册 | 当前为任务型 Agent 系统；现有代码不支持分布式多 Agent 协作或完整 MCP 传输生命周期 |

协议修改参考 [MCP 2024-11-05 生命周期](https://modelcontextprotocol.io/specification/2024-11-05/basic/lifecycle) 和 [JSON-RPC 2.0 请求、通知与响应规则](https://www.jsonrpc.org/specification)。当前 HTTP JSON-RPC 方法子集尚无 SSE、Streamable HTTP 会话与完整连接生命周期管理，不能据此宣称与任意 MCP SDK 完全互通。

## 启动配置变化

本地 macOS/Linux 演示：

```bash
export SMARTCS_SECURITY_JWT_SECRET="$(openssl rand -base64 48)"
export SMARTCS_SECURITY_DEMO_ISSUER_ENABLED=true
./mvnw spring-boot:run
```

JWT 密钥不再有公开默认值。`.env.example` 中的占位值必须替换，直接复制后不会启动成功。Maven/IDE 不会自动读取 Compose 的 `.env`，需要在启动进程的环境中配置。测试专用密钥仅在 `src/test/resources/application.properties` 中，不用于部署。

基线实验默认关闭；需要对照时，在独立进程启用 `SMARTCS_EVAL_BASELINE_ENABLED=true`，同时使用 memory/local/memory 三个模式。默认发布行为不能恢复为对外开放实验端点；基线故意没有确认门控，属于实验变量。以上限制约束配置与入口，实验进程仍需与实际服务分开运行。

用户偏好 HTTP 响应格式保持兼容；Java 存储 API 改为显式传递租户，避免旧的单 userId 重载重新引入跨租户访问。存储仍是有 TTL 和容量限制的进程内实现，重启会丢失。

## 可用于简历的表述

项目名称：**面向电商客服的可控 Agent 系统**。

项目介绍：基于 Spring Boot 与 LangChain4j 实现任务型客服 Agent，通过确定性 Workflow 管理订单、退货、知识问答和人工转接，并以统一能力网关约束业务调用。

建议从以下四条选择三到四条；测试数量可放项目说明或仓库文档，简历优先保留设计与业务价值。

- 设计 Runtime、Workflow、Action Handler、Capability Gateway 分层及自动注册机制，支持多轮任务恢复、Local/MCP Provider 替换和独立渠道资格策略，新增业务无需修改核心执行循环。
- 以已验证 JWT Principal 为可信身份源，结合角色权限、Skill 白名单、资源归属和退货提交前确认限制业务操作；会话及偏好按租户与用户隔离，并通过跨租户和实验入口回归验证边界。
- 针对退货和人工转接中的重复请求、超时及结果未知，设计稳定幂等键、租约、调用前 Outbox 和人工复核机制，配合有界执行器及整轮预算控制故障影响。
- 按政策与故障知识构建差异化 RAG，支持关键词/Qdrant 混合召回、RRF 融合、规则重排与独立降级，并以 Trace、Monitor、反馈审核和 Eval 回归连接质量改进流程。
