# 项目 1 学习总结：ecommerce-customer-service-skill-mcp

## 项目概述

这是一个**电商智能客服 Agent 项目**，采用分层解耦架构，把客服策略、对话编排、业务工具和知识检索拆分为独立的层次。

---

## 一、架构设计

### 分层架构

```
Agent Runtime    → 会话管理、执行循环、LLM 调用
Skill            → 客服策略、意图判断、回复组织
MCP Tools        → 业务能力边界（订单、物流、售后等）
Knowledge Search → 静态知识召回
```

### 各层职责

| 层次 | 负责 | 不负责 |
|------|------|--------|
| Agent Runtime | 会话状态、Skill 选择、Action 执行 | 具体客服业务规则 |
| Skill | 意图判断、客服流程、追问策略 | 直接访问数据库或外部系统 |
| MCP Tools | 订单、物流、支付、售后等业务能力 | 决定客服话术 |
| Knowledge | 商品、政策等静态知识召回 | 用户订单等私有数据查询 |

---

## 二、Skill 设计（重点）

### Skill 是什么？

**Skill 不是单个 Prompt，而是领域策略包**。

它描述客服在某个业务域内如何工作：
- 如何识别意图
- 如何追问缺失信息
- 什么时候调用 MCP
- 如何解释工具结果
- 哪些场景必须转人工
- 回复时应遵守什么口径

### Skill 文件结构

```
skills/customer_service_core/
├── manifest.yaml                 # Skill 元数据、能力声明、意图和优先级
├── SKILL.md                      # 主策略说明
├── agents/openai.yaml            # 面向模型运行的配置
└── references/
    ├── persona.md                # 客服角色与表达风格
    ├── intent_taxonomy.md        # 电商客服意图分类
    ├── conversation_policy.md    # 多轮对话策略
    ├── knowledge_playbook.md     # 知识查询策略
    ├── mcp_policy.md             # MCP 工具调用边界
    ├── order_playbook.md         # 订单相关流程
    ├── after_sales_playbook.md   # 售后流程
    ├── complaint_playbook.md     # 投诉处理流程
    ├── handoff_policy.md         # 人工转接规则
    ├── response_templates.md     # 回复模板
    └── evaluation_cases.md       # 评估用例
```

### SKILL.md 的内容

**主策略文件**，包含：
1. **角色定义** - AI 是谁
2. **边界说明** - 什么能做、什么不能做
3. **工作流** - 处理流程
4. **参考资料** - 引用哪些 reference 文件
5. **场景路由** - 不同意图用什么工具
6. **输出期望** - 返回什么类型的 Action

### manifest.yaml 的内容

**结构化元数据**，包含：
- name: Skill 名称
- version: 版本号
- description: 描述
- domain: 领域
- priority: 优先级
- capabilities: 能力列表
- intents: 意图列表
- required_mcp_tools: 必需的 MCP 工具
- optional_mcp_tools: 可选的 MCP 工具
- handoff_policy: 转人工策略

```python
    return MarkdownSkill(definition)
```

### 2. 运行时使用

**MarkdownSkill.next_action()** 核心流程：

```
1. 检查是否有 LLM 观察结果 → 返回 FinalAnswerAction
2. 检查是否有工具执行结果 → 生成回复
3. 检查是否有图片 → 路由到视觉分析
4. 规则路由（关键词匹配）
5. 如果没有规则路由 → 调用 LLM 做意图识别
6. 根据路由结果选择 Capability
7. 如果缺信息 → AskUserAction（追问）
8. 生成 LLMAction 回复
```

### 3. System Prompt 构建

```python
def _build_system_prompt(context):
    parts = [
        "你正在运行一个可插拔 Agent Framework...",
        self._definition.skill_body,  # SKILL.md 内容
    ]
    # 根据意图选择性加载 reference 文件
    for name in self._selected_reference_names(context):
        content = self._definition.references.get(name)
        parts.append(f"# Reference: {name}\n{content}")
    return "\n\n".join(parts)
```

**关键设计**：不是加载所有 reference，而是**根据意图选择性加载**。

## 四、意图识别设计

### 两层识别

**第一层：规则路由**（快速、确定性高）
```python
def _rule_route(message):
    if "退款" in message or "退货" in message:
        return {"intent": "after_sales_policy", "capability": "knowledge_search"}
    if "投诉" in message or "人工" in message:
        return {"intent": "handoff", "capability": "human_handoff"}
    ...
```

**第二层：LLM 识别**（语义理解强）
```python
def _intent_recognition_action(context):
    return LLMAction(
        purpose="intent_recognition",
        prompt="请识别客服意图，输出 JSON...",
        context={"user_message": message}
    )
```

### 路由结果

路由结果包含：
- intent: 意图
- capability: 要调用的能力
- references: 要加载的 reference 文件
- fallback: 降级策略

## 五、Action 系统

### Action 类型

| 类型 | 作用 | 例子 |
|------|------|------|
| LLMAction | 调用 LLM 生成回复 | 意图识别、回复生成 |
| CapabilityAction | 调用 MCP 工具 | 订单查询、知识搜索 |
| FinalAnswerAction | 最终回复 | 返回给用户 |
| AskUserAction | 追问用户 | 缺订单号时追问 |

### Action 执行流程

```
Skill.next_action() → 返回 Action
        ↓
Executor 执行 Action
        ↓
执行结果存入 Observations
        ↓
Skill.next_action() → 根据结果决定下一步
```

## 七、知识检索设计

### 不是传统 RAG

项目没有用向量库，而是用**本地、可解释的检索流程**：

1. 使用 Markdown 知识卡片保存内容
2. 构建 L0/L1/L2 层级索引
3. 通过规则型 QueryPlan 将用户问题拆成多路查询
4. 使用倒排索引召回候选
5. 基于标题、关键词、正文等做轻量 rerank

### 优势

- 冷启动成本低
- 检索过程可解释
- 知识维护方式接近业务文档
