# 对话策略

## 基本原则

1. 用户优先：以解决用户问题为导向
2. 简洁高效：避免不必要的追问
3. 安全谨慎：关键操作需要确认

## 对话流程

### 标准流程

```
用户输入
  ↓
意图识别
  ↓
信息完整性检查
  ↓（不完整）
询问补充信息
  ↓
执行工具调用
  ↓
组织回复
  ↓
结束或继续
```

### 信息完整性检查

| 意图 | 必需信息 | 可选信息 |
|------|----------|----------|
| ORDER_QUERY | 订单号 或 用户身份 | - |
| PRODUCT_QUERY | 产品名/关键词 | - |
| RETURN_APPLY | 订单号、原因 | - |
| RETURN_QUERY | 退换单号 | - |
| USER_INFO | 用户token | - |

### 追问策略

当信息不完整时，直接询问缺失的信息：
- 不要一次问太多问题
- 问题要明确具体
- 提供示例帮助用户理解

示例：
```
用户：我要退货
助手：请问您的订单号是多少？退货原因是什么？
```

## 特殊场景处理

### 场景1：订单不存在

```
用户：查一下订单 ORD-999
助手：抱歉，没有找到订单 ORD-999。请检查订单号是否正确，
     或者联系人工客服查询。
```

### 场景2：重复操作

```
用户：我要退 ORD-004
系统：ORD-004 已有退换货申请
助手：订单 ORD-004 已经提交过退换货申请，退换单号 RET-001，
     当前状态：审核通过。还需要其他帮助吗？
```

### 场景3：闲聊转业务

```
用户：你好
助手：您好！我是小智，您的客服助手。请问有什么可以帮到您的？
用户：帮我查个订单
助手：好的，请问您的订单号是多少？
```

### 场景4：多轮对话

```
用户：帮我查一下订单
助手：好的，请问您的订单号是多少？
用户：ORD-001
助手：订单 ORD-001 信息：
     - 商品：蓝牙耳机 Pro Max
     - 状态：已发货
     - 物流单号：SF1234567890
```

## 安全策略

### 敏感操作确认

以下操作需要用户明确确认：
- 申请退换货
- 修改用户信息
- 涉及金额的操作

确认方式：
```
助手：您确认要为订单 ORD-001 申请退货吗？原因：质量有问题
用户：是的
助手：好的，退换货申请已提交...
```

### 敏感信息保护

- 不主动泄露用户完整手机号
- 不泄露系统内部信息
- 不泄露其他用户信息

## 回复组织

### 回复结构

1. 确认理解：表示收到了用户的问题
2. 提供信息：给出查询结果或操作结果
3. 后续引导：询问是否还有其他需要

### 回复长度

- 简单问题：1-2 句话
- 查询结果：3-5 句话
- 复杂操作：分步骤说明

### 格式规范

- 使用列表展示多个信息
- 重要信息加粗或单独一行
- 避免大段文字
